# 학습 디텍터 설계 — 사용자가 녹화한 동작으로 자세 상태를 kNN 분류

2026-09-14 · 상태: 승인됨(채팅) · 구현 전

## 목적

각도 임계값 규칙은 카메라 각도·체형·전환 동작(걷기, 철봉 잡기)에 취약하다.
사용자가 운동별로 1회 동작을 여러 번 녹화하면, 그 관절 좌표를 그대로 모델로 삼아
프레임마다 자세 상태를 분류하고 상태 전이로 횟수를 센다. 영상은 저장하지 않는다.

## 범위

- 학습 모드 페이지 `/learn`: 녹화·저장·목록·삭제
- 샘플 저장소: Neon `pose_samples` 테이블 + API
- 학습 디텍터 `lib/detectors/learned.ts`: 기존 `ExerciseDetector` 인터페이스 구현
- 자유 운동·루틴 모드에서 샘플이 충분한 운동은 학습 디텍터로 자동 교체
- 디버그 묶음에 분류 결과 기록

범위 밖: 서버 학습, 신경망, 영상 저장, 다른 사용자 샘플 공유.

## 데이터

### 샘플 (한 번의 녹화)

```ts
interface PoseSample {
  id: string;            // uuid
  exerciseId: ExerciseId | 'none';   // 'none' = 아무것도 아님(부정 샘플)
  view: 'front' | 'left' | 'right' | 'diagonal';
  height: 'floor' | 'waist' | 'eye';
  fps: number;
  frames: number[][];    // 프레임별 33*4 (x, y, z, visibility) — 정규화 전 원본
  /** 사용자가 타임라인에서 표시한 구간(프레임 번호). 구간 밖은 none 으로 쓴다 */
  marks: { start: number; end: number; bottom?: number };
  createdAt: number;
}
```

- 녹화는 시작 버튼~완료 버튼 사이. 2초 미만·15초 초과는 거부한다.
- 저장은 원본 좌표. 정규화는 읽는 쪽에서 한다(정규화 방식이 바뀌어도 재녹화 불필요).
- DB: `pose_samples(id, user_id, exercise_id, view, height, fps, frames JSONB, created_at)`.
  사용자별 격리. 한 샘플 30~60KB, 운동당 30개 × 9종 → 수 MB 수준.

### 프레임 정규화 (`lib/learned/normalize.ts`)

1. 신뢰도 0.3 미만 관절은 좌표를 0으로 두고 마스크 처리
2. 엉덩이 중점을 원점으로 이동
3. 몸통 길이(어깨 중점~엉덩이 중점 거리)로 나눠 크기 통일
4. x, y만 쓴다(z 는 흔들림이 커 제외) → 66차원 벡터
5. 좌우 반전 증강: 학습 샘플마다 x 부호를 뒤집고 좌우 관절 인덱스를 바꾼 사본을 추가

### 구간 표시 (사용자) 와 상태 라벨 (`lib/learned/label.ts`)

녹화 직후 막대 인형 재생과 타임라인을 보여주고 사용자가 손잡이로 구간을 잡는다.
자동 추정은 손잡이의 **기본 위치**로만 쓰고, 최종 라벨은 사용자의 표시를 따른다.

- 모든 종류: `start`~`end` 가 그 운동. **구간 밖 프레임은 자동으로 `none`** 샘플이 된다
  (자리 잡기, 돌아오기 같은 전환 동작이 녹화마다 부정 샘플로 쌓인다)
- rep 운동(스쿼트·푸시업·풀업·로우): `bottom` 손잡이가 하나 더 있다. 기본값은 구간 안에서
  `start` 프레임과의 정규화 거리가 최대인 프레임. 라벨은 `start`·`end` 근처(바닥 거리의 25% 이하) → `top`,
  `bottom` 근처(70% 이상) → `bottom`, 그 사이 이동 중 프레임은 버린다
- hold 운동(플랭크·사이드 플랭크·한발 서기·데드행): 구간 전체가 `hold`. 기본 손잡이는 클립 앞뒤 20% 를 뺀 위치
- `none` 항목으로 찍은 샘플: 구간 전체가 `none`. 기본 손잡이는 클립 전체

표시값은 샘플에 저장하고 목록에서 다시 열어 고칠 수 있다.

프레임 선택(모든 종류 공통):
- 각 상태 안에서 **0.1초 간격**으로 뽑는다. 원본은 30fps 전부 저장돼 있으므로 간격은 읽을 때 바꿀 수 있다
- 샘플당 상태별 상한 20개 — 넘으면 시간 순 균등 솎기. 느린 동작이 빠른 동작보다 과대표되지 않게 한다
- 전체 데이터셋에서 운동·상태별 상한 300개 — 넘으면 오래된 샘플부터 균등 솎기. kNN 거리 계산량의 천장이다

결과: `{ exerciseId, state, vector[66] }` 목록. 이것이 kNN 의 전체 데이터셋이다.

## 추론 (`lib/learned/knn.ts`, `lib/detectors/learned.ts`)

- k = 5, 거리 = 마스크를 반영한 유클리드. 상태별 표 수 / k 가 그 상태의 확률
- EMA(α = 0.3)로 확률을 평활화해 한 프레임 튐을 막는다
- 프레임에 필수 관절(registry.requiredChains)이 없으면 `none` 확률 1로 처리

rep 디텍터 상태 머신:
- `top` 확률 ≥ 0.6 → top, `bottom` 확률 ≥ 0.6 → bottom. 그 외는 이전 상태 유지
- top → bottom → top 이면 rep 1회. 기존 `minRepMs` 디바운스 유지
- bottom 진입 시 `phase: 'bottom'` 이벤트(띵 소리·굽힘 스냅샷 호환)

hold 디텍터:
- `hold` 확률 ≥ 0.6 을 `isHolding=true` 로 넘겨 기존 `HoldDetector` 를 그대로 쓴다

디버그(inspect): 상태별 확률, 최근접 샘플 id 와 거리, 현재 상태.

## 교체 규칙 (`lib/detectors/registry.ts`)

- `create()` 는 그대로 두고, 새 팩토리 `createDetector(id, samples)` 를 둔다
- 해당 운동 샘플이 **10개 이상**이고 `none` 샘플이 **5개 이상**이면 학습 디텍터,
  아니면 규칙 디텍터. 사용자가 홈의 디버그 배지 옆에서 "규칙 강제" 토글로 되돌릴 수 있다
- 샘플은 자유 운동·루틴 화면 진입 시 `/api/samples?compact=1` 로 한 번 받는다.
  compact 응답은 라벨 추출까지 끝난 벡터 목록(운동당 수십 KB)이다. 원본 프레임은 학습
  페이지에서만 받는다

## 학습 모드 UI (`app/learn/page.tsx`, `components/LearnScreen.tsx`)

1. 운동 선택 칩(샘플 수 표시) + "아무것도 아님"
2. 카메라·포즈 엔진 시작(자유 운동과 같은 코드 경로 재사용)
3. 큰 버튼 하나: "시작" → 녹화 중(경과 시간, 프레임 수 표시) → "완료"
4. 저장 시트: 각도 4택, 높이 3택(직전 값 기본), "저장" / "버리기"
5. 완료 직후 막대 인형 재생 + 타임라인. 손잡이(시작·끝, rep 은 바닥)를 드래그해 구간을 잡는다.
   손잡이를 움직이면 그 프레임의 막대 인형이 바로 바뀐다. 라벨 결과(top/bottom/hold/none 프레임 수)를
   같이 보여주고, bottom 이 0개면 경고
6. 하단에 이 운동의 샘플 목록(시각·각도·높이) + 삭제

## API

- `GET /api/samples` — 내 샘플 메타 목록(프레임 제외). `?exercise=` 필터, `?compact=1` 이면 벡터 목록
- `POST /api/samples` — 샘플 저장(검증: 프레임 수 30~600, 각 프레임 132개 유한수)
- `GET /api/samples/[id]` — 원본 프레임 포함 1건
- `DELETE /api/samples/[id]`

## 디버그 묶음

- 추적 행에 학습 디텍터의 상태별 확률과 최근접 거리를 넣는다(inspect 로 자동 포함)
- 구간 증거(굽힘·폄)는 기존과 동일

## 테스트

- `normalize`: 이동·크기 불변, 반전 증강의 좌우 인덱스 교환
- `label`: 합성 시퀀스(서 있다가 앉았다 일어나기)에서 기본 손잡이 위치와 top/bottom/none 프레임 수
- `knn`: 두 군집 합성 데이터에서 확률
- 학습 디텍터 상태 머신: 확률 시퀀스를 넣어 rep 카운트·디바운스
- 실제 검증은 폰에서 녹화 30개 후 자유 운동으로 확인
